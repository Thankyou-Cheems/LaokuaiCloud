# P2P wiring audit and bounded implementation scope

This audit is source evidence. Actual voice.ruikang.wang membership, voice channel and media are unknown; public /info HTTP200 does not establish them. WebRTC microphone P2P is independent of EasyTier and can be tested once its current backend protocol is deployed. Missing ET provisioning must not block ordinary authenticated community/SFU or independently working WebRTC P2P.

## Existing end-to-end microphone protocol

- Client src/packages/socket/src/utils/joinServerOnce.ts uses server:join → server:challenge → server:verify → server:joined and challengeHostMatches/serverAuth. Preserve server proof, signed identity and rejection paths. src/packages/webRTC/src/adapters/roomCoordinator.ts obtains voice:room:request/granted only with stable server identity.
- Client src/lib/hybridVoicePolicy.ts enables network Hybrid. src/packages/webRTC/src/adapters/HybridVoiceBridge.tsx starts BrowserHybridVoiceSession only after actual SFU PC connected, authenticated socket/account, current server user/session/room, exact publication and connectionEpoch; it inherits real SFU RTCConfiguration. No ET API is called here.
- SDK src/webrtc/hybrid/SocketHybridAuthority.ts requests voice:hybrid:scope/lease/signal/forwarding/release; pair-invalidated retires old pairs. BrowserHybridPeer.ts creates actual RTCPeerConnection and admits only the protected microphone track, with inbound RTP/samples/decoder gates. HybridRouteController.ts and HybridReceivePortAdapter.ts select playable peer receive media only with corresponding forwarding control, and recover SFU. These pieces are implemented, not placeholders needing a new P2P authentication protocol.
- Server src/socket/index.ts registers src/socket/handlers/voiceHybrid.ts. Existing requireAuth/JWT/DB member/channel permission plus current socket/session/publication/room generation bind pair IDs and leases; SDP/ICE relays are bounded and scoped. receiver forwarding calls src/sfu/client.ts requestHybrid → hybrid_command; actual hybrid_result ACK is required. SFU internal/websocket/handler_hybrid.go validates room/source/receiver and applies bounded leases in internal/track/hybrid.go.

## ET engineering that is actually missing

1. Configuration grant producer and main-only consumer: electron/easyTierWindowsProduction.ts only calls readEasyTierExistingConfiguration(root,serverId). electron/easyTierExistingConfiguration.ts requires reviewed activation.json and exact config hash under community-lan/configs; there is no server handler issuing a community-scoped ET grant, no renewal/revoke flow, and no client authenticated import. electron/easyTierCommunityIpc.ts handles leases/enabled/state/prepare/memberships only. Preparing bundled files does not provision a community. Implement a small versioned server grant service/handler, typed client transport, main verifier/atomic config writer and revocation/generation hooks. The grant must bind authenticated community/member/device, configured product-owned network/bootstrap, expiry and server authority proof; credentials must stay encrypted for main or be fetched by a main-only verified authenticated path. No renderer-supplied TOML/path/endpoints or self-asserted approval. Exact trusted server-key transport and secret encryption/storage are not currently designed; complete them as part of this feature, not a guessed field. Preserve separate local driver/local-management authorization; a remote grant cannot set those approvals. Proposed community-lan grant/revoke events would be NEW, not existing protocol names.
2. Authenticated ET identity bindings: electron/windowsEasyTierCliRuntime.ts:70/75 emits bindings:[] even when CLI route info is fresh. easyTierMemberAdapter.ts requires unique, fresh authenticated local/member bindings before projecting members. windowsEasyTierRuntime.ts has a bindings port, but createWindowsEasyTierProduction uses the CLI implementation without such a producer. Implement server-scoped device→native instance/peer binding with actual main-owned node identity evidence, TTL/revoke and collision checks; merely accepting renderer peerId/nickname or connection status is insufficient. Integrate verified bindings into the active CLI runtime sample; unit-test wrong room/community/generation, stale/revoked/colliding IDs and disconnect.
3. Physical media path correlation: SDK BrowserHybridVoiceSession.ts always reports physicalDirectVerified=false; receivePathStats.ts carries selected pair identity/RTT but not authenticated ET route correlation. memberVoiceReceiveTranslator.ts proves selected track and decode separately. Add a private bounded bridge joining the exact selected media candidate endpoint/transport generation to main-owned ET virtual route/peer and the verified member binding, with freshness and explicit direct/server-relay/member-relay/unknown semantics. Direct WebRTC outside ET needs equivalent selected-candidate transport proof, not an ICE type label alone. No address/credential dump into public UI; expiry/unknown never stays direct. Test ownership/scope/selected-track fences before runtime. This is required for physicalDirect claims and future screen policy, not permission to suppress a currently playable voice path.
4. Screen is not implemented as direct-only Hybrid: legacy ScreenShareControl has no mounted caller; BrowserHybridPeer admits microphone only. Leave it unavailable. A future implementation must enforce proven direct transport and pause on loss, never SFU/TURN/ET-relay fallback.

These are bounded source tasks after the UI/logo batch, not permission blockers for ordinary development. No ET or protocol changes were mixed into this commit. Grant producer/consumer and binding/route correlation should be separate reviewed commits with pure positive/negative cases; preserve component boundaries.

## Minimal actual validation and sensitive-operation scope

First test existing WebRTC: two authenticated isolated clients in one dedicated voice room, protected microphone/synthetic media, exact new package and deployed Hybrid community/SFU; prove selected peer track/generation, RTP+decoded samples, actual SFU per-edge pause ACK/counters and recovery. This requires explicit finite client/media/network scope; UI-check mode denies those operations. Coordinate voluntary user-app/port handling, never terminate the user's app or change real profiles.

For ET-backed test additionally approve exact modern core/CLI/drivers, one owned network/TUN, loopback RPC and controlled firewall replacement. easyTierWindowsProcesses.ts:37 supplies 127.0.0.1 portal and whitelist; actual bound endpoints still need observation. Hole punching can bind dynamic :0, so fixed11010-only permission is incomplete; rules must cover necessary dynamic TCP/UDP on exact approved executables/owned interfaces and applicable profile while preserving protected existing private ET/firewall/config state. Backend writes or new credentials await exact deployment/rollback/authority scope. Use current modern payload approval, never consumed old-native approvals. Runtime proof must include cleanup/protected-state comparison; ET joined or logical peer is insufficient.
