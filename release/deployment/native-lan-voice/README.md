## 操作入口

`prepare.ps1 -SourceCommit <40位提交>` 冻结源码、编译并上传私有准备目录；
`run-phase.ps1 -SourceCommit <同提交> -Phase build` 构建且隔离启动，禁止外网和生产挂载。
`-Phase activate` 先备份数据库，只重建 Gryt；失败尝试原镜像回滚。
需要回滚时，对上述精确源码运行 `-Phase rollback`，仅重建 Gryt，恢复原模式；
同时使用旧客户端才恢复旧语音。不要把数据库备份覆盖回仍在使用的数据库。
本次 operator 复核后加强回滚和备份路径保护，重新冻结上传；首次 operator/input
副本仍留在私有准备目录 `*.pre-review.*`，候选镜像和 bundle 未变化。

## 必须明确的切换影响

`NATIVE_LAN_VOICE_ENABLED=true` 是整个 Gryt 实例的语音模式开关。开启后该实例
不初始化或同步 SFU，拒绝旧的 WebRTC 语音加入，保留社区认证、成员、聊天、
频道权限和 EasyTier grant 服务。新旧客户端不能在同一频道混合互通。
这不是兼容旧客户端的后台热更新，不能在用户双人测试期间擅自部署。

准备切换时先记录实际运行镜像、Compose 文件集合和有效配置，保存仅服务端
可读的回滚材料；构建此分支精确提交的 Gryt 镜像，先完成镜像启动检查。
确认具体切换范围后，仅更新 Gryt 镜像及上述开关并重建 `server` 容器。
必须保留现有挂载、账号、聊天、成员、端口、12 人限制及成员中继设置，
不重启 SFU、EasyTier、管理代理，不改 DNS/防火墙/虚拟网络配置。

回滚使用记录的原镜像和原 Compose 文件集合，仅重建 Gryt。
原数据库不变，没有本实验要求的 schema 迁移，也不清空任何成员身份。

## 验收

1. 新后端 `server:info` 宣告 nativeLanVoice 和协议版本，旧客户端语音请求
   得到明确拒绝，聊天和 EasyTier 仍可用。
2. 两端用新版正常恢复社区；不进入语音时 EasyTier IP/MagicDNS 继续存在。
3. 点选同一频道，不输入音频 IP/密钥，私有快照发现对端，原生进程产生收发包；
   双方确认真实听感和静音/PTT/各成员音量，不能仅凭包计数判定听到了声音。
4. 持续通话、主动换房、管理员移频、成员离开/返回、普通静音、服务端禁言和
   耳聋恢复。确认普通静音不更换房间密钥、不重启所有人的音频 helper。
5. 语音退出/失败时 ET core PID、社区虚拟地址和游戏连接保持；应用整体退出
   才回收自己拥有的 ET。记录实际首次退出耗时。
6. 模拟短暂控制面失败，音频只使用原租约，不无限续命；明确失权立即停止。
7. 双机通过后再测 12 人、直连比例和中继出口。6 Mbps 全中继容量尚未保证。
