# Shared sending speech evidence and automatic gate

`audio.noiseGateMode?: "manual" | "automatic"` defaults to manual. `audio.transmitSpeechActivityEnabled?: boolean` defaults to false. Either automatic or the speech opt-in enables the new graph. Manual with no speech opt-in preserves the frozen processing order and threshold behavior. Manual plus speech opt-in retains manual threshold decisions but uses the new processing order to carry speech evidence correctly. No receive gain or receiving VAD controls this gate.

`audio.transmitEligible?: boolean` is the embedder's actual current speak permission; omitted fails closed at the final physical publication gate whenever automatic or speech opt-in enables the new graph. This includes manual mode with speech enabled and manual threshold zero. Legacy manual with both features off preserves its existing eligibility behavior. `useSFU` sets `setTransmitConnected` only for an actually connected peer and its registered live enabled original microphone publication sender. This method grants no permission and introduces no useMicrophone/useSFU singleton cycle. User/server mute, unheld PTT, suppression, recovery/fault, absent permission/connection, ended microphone and no handles cannot light the indicator.

`transmissionState.publicationRevision` is the last accepted actual audio-boundary ACK revision, undefined before an ACK or after processor failure. `publicationAcknowledged` means that ACK matches the current requested control revision. `publicationBlocked` is the actual blocked value in that ACK, not the requested value. During a pending change the last revision/blocked value can remain, but acknowledged is false. Consumers must check all three together; neither ready status nor blocked alone confirms the current gate. Processor failure retires its ACK and ignores subsequent messages from that failed/retired node.

A staged disabled publication clone does not qualify as the live original publication sender. After transaction-bound target policy confirmation and a current acknowledged closed final gate, replace the staged sender with the original stable protected publication track while its PCM remains zero. Only after replacement and actual connected-peer/live-original-sender verification may connection eligibility release the gate. Recheck transaction/peer/track/policy/closed ACK after asynchronous replacement. Enabling the clone alone cannot establish this qualification. This ACK describes local audio processing, not remote reception or a WebRTC encoder queue flush.

`useMicrophone().transmitSpeechActivity` is always boolean. `transmitSpeechActivityState` is separately available/unavailable. Available includes `source: "rnnoise" | "webrtc_rnn"` and `noiseSuppression: {status:"applied"|"disabled"|"unavailable",reason?:...}`. A 44.1k NS request uses the sole supported fallback analyzer and reports NS unavailable with `unsupported_sample_rate`; it does not claim denoising was applied. Unavailable reasons include disabled, native/rate unsupported, awaiting context, loading, failed and stale. Never use a state object as boolean speech. `isTransmitting`, meters and RTP counters remain distinct from speech detection and remote delivery.

`getAutomaticNoiseGateState()` returns available `{open,floorDbfs,probability}` or unavailable reason manual_mode/platform_unsupported/unsupported_sample_rate/processor_loading/processor_failed. It is a diagnostic snapshot at about 21ms cadence. Null floor means unlearnt; probability can be null before the first decision. The snapshot does not run the gate or drive speech truth.

## Graph and alignment

The new graph retains capture-fresh barrier, input gain, optional send AGC/compressor and existing native limiter/4x soft clipper, then places the one active model after them. With NS on, existing RNNoise worker inference returns probability and analysis-window RMS together with the actual processed PCM. Its output queue stores those fields with each generation/sequence chunk; carrier output changes only when that chunk is actually emitted. Underfill has zero PCM and invalid zero carrier. Sequences wrap at 2^20, well below Float32 adjacent-integer aliasing.

With NS off/unavailable, the unchanged frozen WebRTC RNN analyzer consumes one 10ms block and releases the same untouched Float32 PCM block with its decision carrier. This introduces a known 10ms buffer; 44.1k and 48k markers prove exact waveform/level parity over 87,879 and 95,520 samples respectively. This analyzer does not denoise, normalize or change PCM. It has one handle and a fixed 16MiB heap. NS on reuses existing RNNoise, measured heap 20,578,304 bytes, and never instantiates a second active inference. Pending RNNoise initialization closes the new gate rather than activating a concurrent fallback. A fault destroys RNNoise before enabling fallback. Removing all handles or switching modes disposes the respective model/ports; browser garbage-collection timing is not promised.

Graph-private zero-delay gain taps carry PCM and metadata to the same gate worklet. The gate performs a final finite sample clamp to +/-10^(-1/20), then its speech/valid carrier follows the same direct AudioNode path to the stable `TransmissionBoundary`. There is no intervening MediaStream roundtrip, native compressor or oversampler after evidence. The boundary computes speech from the same output block, its own actual blocked state, permission/connection control, carrier and actual nonzero finite PCM. Main-thread code can synchronously clear/reject old revisions; it does not synthesize a true speech value by timer AND. The final controller remains the authority for mute/PTT/Squad recovery and ACK. Stable publication selectors still precede every raw fallback.

RNNoise's pinned implementation uses a 20ms analysis window, delayed spectrum and overlap-add synthesis. Its returned VAD is the decision window used during the model call that produces the paired output chunk, not a unique truth label for each sample. The measured impulse peak delay is 960 samples/20ms plus the existing asynchronous worker queue. Waveform pre-ringing prevents a unique pointwise classification claim. See [pinned implementation](https://raw.githubusercontent.com/xiph/rnnoise/70f1d256acd4b34a572f999a05c87bf00b67730d/src/denoise.c) and [package build pin](https://raw.githubusercontent.com/shiguredo/rnnoise-wasm/2025.1.5/build-rnnoise.sh).

The order change is necessary because measured Chromium native compressor delay is 6ms each, while 4x WaveShaper adds a 192-sample peak delay and an amplitude-dependent impulse spread. These measurements are not a portable browser delay contract. Moving NS after AGC/compression changes its input and potentially its sound. No listening, game-load, first-syllable naturalness or device quality certification is claimed.

## Automatic decisions and resets

Only finite nonzero, eligible model frames with probability <=.05 learn floor. Floor is bounded -90..-20dBFS; it rises with .002 smoothing and falls with .2. At least ten trusted frames are needed before lower-confidence SNR candidates can open. Probability >=.95 opens immediately even for quiet input. Otherwise >=.7 plus >=10dB SNR needs two adjacent frames; an open gate uses .6 and 6dB hysteresis. Configured noiseGateRelease provides hangover, but hangover alone is not speech. The existing 10ms sample ramp remains. These are conservative initial constants, not calibrated whisper recognition.

Zero-fill, muted/disconnected/suppressed/recovering or invalid frames do not learn. Hard eligibility edges discard partial/output chunks and reset the floor; RNNoise resets reject old generations. Fallback model history resets in control handlers, with ABI views rebound because frozen gryt_reset replaces State. Device/capture generation, input volume, AGC/target/compressor changes reset evidence; significant live AGC gain changes invalidate floor. Nothing persists across devices. There is no prerecording buffer to replay after a hard gate. Unsupported rates remain explicit unavailable.

An opted-in hard eligibility release also keeps the final gate closed through the existing fresh-audio recovery. Model-only queue resets cannot remove native compressor/oversampler history: an actual marker reproduced old PCM after a short closed interval. The new path first rebuilds the native graph and observes its capture ACK, then resets the shared RNNoise and awaits actual fresh model output. Fallback handles are disposed/recreated with the capture generation. A new forbidden edge cancels the pending generation; disabling both opt-ins cancels their pending recovery and clears its pipeline waiter while retaining current user/server/PTT reasons and existing processor failures. If legacy suppression remains enabled, its pending fresh barrier restarts under a new legacy generation before opening. The legacy fresh path retains its prior order.

Fresh recovery deliberately discards buffered native/model samples rather than replaying them. One muted synthetic run observed about 41–43ms wall wait before an open ACK; these poll-quantized values are not a latency guarantee, a listening assessment or an encoder flush. A requested 4ms main-thread interval measured 0ms in the final run (the earlier failed run measured 10.67ms) on the browser's coarse audio clock, so it is not advertised as an exact 4ms audio interval. The stable boundary recorder observed zero old marker samples after actual reopen in fallback connection/PTT and RNNoise connection/PTT/Squad cases. Device/OS/browser capture buffers and already submitted encoder/network packets cannot be recalled by rebuilding SDK native nodes.

The final sample clamp has zero added delay and a mathematical finite ceiling. It is an emergency protection after RNNoise, not an additional loudness stage. Real native-DSP-to-RNNoise fixtures (quiet/normal/max-gain public speech and seeded broadband/synthetic fan/keyboard) stayed below the ceiling with zero clamp samples in this run. A deliberately over-range marker exercises the clamp. Synthetic fan/keyboard are test waveforms, not recorded devices. The three noise fixtures had zero >=.95 speech frames; this is not a universal classifier guarantee.

## Validation and retained failures

Run `npm run typecheck`, `npm run build`, `node scripts/generate-transmit-speech.mjs --check`, `node scripts/check-adaptive-transmit-gate.mjs`, `node scripts/check-adaptive-send-markers.mjs`, and `node scripts/check-adaptive-send-headless.mjs <existing-vendor-node_modules>`. Headless uses muted Chromium, a loopback server, blocked real getUserMedia and BelowNormal Node priority. Actual RNNoise worker/public PCM, NS transitions, permission, PTT, suppression/rebuild/recovery, disconnect, no handles, stable publication and genuine test-only processor throw pass. Manual plus speech opt-in with threshold zero measures 4,800 exact zero publication samples in each absent-permission/disconnected/revoked-permission case, and nonzero samples when allowed/reconnected. These publication-stream observations allow 100ms to drain the test recorder's MediaStream roundtrip and do not certify encoder/network buffers. Freshness markers observe the actual stable AudioWorklet boundary directly, without that roundtrip. All 40 transmission checks (25 existing plus 15 physical eligibility/actual ACK/fresh generation/opt-in exit cases) and publication-over-raw checks pass.

The first genuine NS transition exposed stale carrier: old React graph cleanup detached shared RNNoise directly from shared gate after the new graph had connected them. Private per-graph taps and targeted cleanup fix this without disconnecting the new graph. A control edge arriving before worker-port attachment could also strand reset waiting; pending reset now sends when the port attaches, with a marker regression. The superseded independent observer source/tests are removed from the final tree. The earlier prototype and its extra 16MiB are preserved only as investigation in transmit-speech-prototype-investigation.md and commit 0ed62d5; the final hook does not instantiate it.
