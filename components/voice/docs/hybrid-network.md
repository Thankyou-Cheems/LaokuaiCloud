# Experimental voice routing source checkpoint

This source delta adds a browser WebRTC peer, authenticated application-server pair signaling and an SFU forwarding-lease implementation. It is **not runtime-accepted or installed in the stable client**. Network fixtures are paused by the user's firewall-prompt stop instruction. No new listener, real PeerConnection, capture, network configuration, firewall rule or production deployment was started for this delta. The stable client stays audio-only and SFU-based. Missing/disabled server capability stays `unsupported`; never manufacture an ACK or media-ready state.

The inherited controller contract and simulation evidence are in `hybrid-prototype.md`. That document describes the earlier frozen simulation baseline, not verification of the new network adapters. `HybridState.kind` remains `hybrid-prototype` to identify the experimental API. Controller `active` describes adapter capability, while individual routes report actual selection and recovery.

## Concrete public API and ownership

Web exports add `BrowserHybridPeer`, `BrowserHybridPeerOptions`, `borrowHybridPublication`, `SfuDecodedAudioMonitor` and `SfuAudioEvidence`. Engine/native-safe exports add `SocketHybridAuthority`, `HybridSocketTransport`, `HybridAuthorizedSnapshot`; native imports never construct browser peers. The API is separate from ordinary singleton hooks; the host must explicitly integrate its lifecycle. No client wiring or network enablement is included here.

`SocketHybridAuthority` borrows the existing authenticated Socket.IO connection and a runtime-only token getter. Call `await authority.refresh()` before creating an enabled `HybridRouteController`. This authenticates a capability probe and obtains server-issued instance/room generation, actual server user IDs, current socket sessions and current registered microphone publication IDs. The constructor does not create a second auth connection. Subscribe on roster/permission changes, refresh, and reconcile current physical routes; stale async ACKs are rejected across socket/authority generation changes. Dispose the authority and controller on server/room/session teardown.

`borrowHybridPublication(microphone, currentSfuPc)` requires the exact final protected SDK publication track to be the current connected SFU sender track, with acknowledged publication revision. It rejects raw/processed-only capture and track-ID collisions. Every peer borrows that same final PCM track and never calls capture, clones raw media or stops it. User/admin/PTT/Squad gates therefore precede every sender. Publication IDs come from authenticated application-server `ci.streamID`, not a guessed original/replacement MediaStream ID. Browser SDP stream wrappers need not have the same ID as the server's current publication registration.

Each `BrowserHybridPeer` gets explicit `rtcConfiguration`, `microphoneCodec` and trusted `channelMaxBitrateBps`. No public STUN server is added. A channel ceiling is applied before SDP exchange; authentic remote caps further bound the final sender. `getMicrophoneCodecState()` returns a detached requested/effective/remote/readback snapshot, with `rtpVerified: false`. Invalid profiles, sub-6000 caps, setParameters failures and negotiation mismatches fail the peer visibly and retain/recover SFU. Actual startup RTP cap enforcement still requires the paused browser test.

`SfuDecodedAudioMonitor` shares one stats poll across physical microphone routes of the existing SFU PC. Bind exact stream/track objects and a current-generation predicate. Post-restore-ACK checkpoint waits out an older stats flight, then makes a new read; that checkpoint itself is never fresh media. A later increase of both track-scoped packet and decoded-sample counters is required. Missing counters, reset, stale binding and a five-second deadline are failures. Browser peer readiness similarly requires increasing packets and decoded samples, a live audio track and connected PC; sample-only concealment cannot refresh readiness. These are actual API implementation paths tested with deterministic stand-ins so far, not an actual decoded-PCM demonstration.

`HybridReceiveInput` owns the sole edge into the already existing DSP/manual/bus path. Keep the one physical route across aliases. Dispose the selector before SDK route cleanup, and rebind receiver track ID/generation on every actual selection callback. Preserve participant receive history independently of the changing live track. `none` immediately clears the live identity. Do not let another graph writer reconnect the SFU source while the selector owns it.

## Wire implementation and default behavior

Application server: explicit `VOICE_HYBRID_ENABLED=true`, default disabled. Events are `voice:hybrid:scope`, `lease`, `signal`, `forwarding`, `release`; responses include protocol `v:1`. `scope` reports supported only after a real SFU probe. Signed JWT verification, current database membership/permissions, live socket registration, same active room, actual microphone publication and session are rechecked. Server-minted UUID pairs choose one deterministic initiator, expire after 30 seconds, bound ordered canonical SDP/ICE, and invalidate on mute/deafen/move/leave/session/publication changes. Ambiguous duplicate user sessions cannot become peer routes. Tokens and credentials stay runtime-only and are never evidence payloads.

SFU: explicit `SFU_HYBRID_ENABLED=true`, also requires authenticated client tokens and audio-only policy. The application server reuses its registered authenticated SFU WebSocket; `hybrid_command`/`hybrid_result` commands carry bounded command IDs. A probe alone cannot pause anything. Forwarding resolves the two admitted current room PeerConnections from their signed app-socket sessions and resolves the exact audio publication. It applies the gate to that source→receiver RTP forwarding edge under the mutex covering actual Track.Write. An applied ACK follows prior writes; already in-flight packets cannot be recalled.

Forwarding defaults ON. Pause lasts at most ten seconds, checked by the RTP thread; browser or application timers cannot keep a route paused indefinitely. Authority revision rejects older writes; an old or unbound restore cannot open a different active pair. App-side pair/operation fencing rejects stale cleanup before sending a command. A null cleanup is accepted only when no active app pair conflicts; if the SFU still holds another active pair, it rejects until expiry rather than acknowledging an unsafe restore. The SFU trusts the registered application server's pair authority; it does not independently cryptographically sign browser pair IDs.

Keep default ten-second controller pause leases for this adapter. The older generic simulator permits higher configurable lease durations; the real protocol rejects pauses above ten seconds. Lost/failed ACKs never authorize P2P selection. Pair revocation detaches and closes the old peer before attempting fresh SFU recovery. Server-side permissions control signaling and SFU gates; compliant SDKs close direct media on revocation. A hostile modified endpoint is not physically prevented from continuing an already established direct connection solely by a signaling revocation event.

## Audio quality and bandwidth contract

Latest product candidates are **SFU 48000 bps, P2P 64000 bps**, mono Opus, 20ms, VBR/DTX/FEC requested. P2P 48000 is also a listening candidate; if 64000 has no stable perceptual benefit, choose 48000. 24000 is an explicit savings/degraded tier and is not represented as meeting the requested TeamSpeak top-quality target. These are future opt-in host configuration candidates, not a change to frozen defaults or production permissions. The user's 7.71KiB/s reference is a TeamSpeak channel-quality display, not measured room traffic.

Use `connection.microphoneCodec` for the SFU sender and `BrowserHybridPeerOptions.microphoneCodec` for each peer sender. The final effective cap is the minimum of the requested bitrate, authenticated channel/admin cap and authentic remote receive cap. Never raise a 16000/24000 administrative cap to implement a 48000/64000 target. Below the Opus minimum, close/fail visibly rather than silently exceeding the cap. A mismatched peer profile is observable and currently conservatively fails to SFU. The existing SFU offer policy fixed at 24000/20 must be changed in a separate authorized source revision before a truthful 48000 SFU claim is possible.

Shared capture/DSP and one protected PCM publication do **not** imply shared encoding: every RTCRtpSender/PeerConnection has separate codec parameters and potentially a separate Opus encoder. Per-peer CPU and aggregate uplink must be measured. Receive history/DSP/manual gain remain associated with participant and physical route; sender bitrate changes do not create independent AGC histories. Mono voice uses the usual 48kHz Opus clock; do not change Windows device format or chase 96/192kHz or stereo output specifications. Listening, reliability and latency outrank larger numeric settings.

## Capacity acceptance and future screen policy

Primary matrix: 15–20 total online users in multiple rooms, e.g. 4×5 or 2×10, each room with 0/1/2 simultaneous speakers, mostly direct peers with a smaller set of SFU fallback receivers. Record each source's actual SFU receiver count, per-path packet/payload/header counters and actual SFU egress. No cross-room fanout. Silence DTX, source→receiver offload ACKs, admin moves, reconnect/permission/replacement and fallback are independent assertions. Twenty same-room all-speaking/all-relay remains an abnormal pressure boundary, not the reason to lower normal quality. There is no actual mixed-path or 20-user acceptance in this checkpoint.

Stable media remains microphone audio only. **Future screen media requires positively verified direct P2P**: no SFU, TURN or EasyTier media relay. Signaling may use the server. Direct failure prevents sharing; loss of verified direct path immediately pauses video for the affected receiver and never silently selects a relay. A host ICE candidate over EasyTier is insufficient proof of its underlying transport; unknown underlying path must refuse screen media. The existing voice SFU fallback is unaffected. This audio adapter rejects every non-audio SDP media section and is not reusable as permission to add screen tracks.

## Verification boundary and resume

No-network SDK tests use the real adapters/controller with fake RTC/sockets/stats; real local JWT and temporary SQLite exercise server authorization with stubbed SFU ACKs. The pure Go lease-state test imports only the standard library and no Pion code. Production-source builds check TypeScript and Go compilation. None establishes real peer negotiation, server-to-SFU ACK transport, actual Track.Write suppression, decoded synthetic PCM, packet loss/FEC, listener safety, device latency or perceptual quality.

The Windows fixture stop remains binding. Earlier Pion tests using only loopback IPFilter can still create multicast DNS sockets because the Pion/ICE defaults query mDNS. The future test wrapper now explicitly disables mDNS in source, but it has not been executed or shown free of firewall prompts. Do not relaunch tests, permit a firewall dialog, change firewall rules or claim a verified no-popup path. Resume requires separate permission and verified containment; then first prove two real authenticated SDKs plus actual Pion counters/PCM and only later the scoped multi-room capacity matrix. Preserve the prior capacity failures rather than counting successful launch as acceptance.
