# Local receive long-term leveling

This local receive path never instantiates the legacy ReceiveLeveler. The library option `audio.receiveLevelingEnabled` remains false by default; the private client chooses its own default. There is no newly published npm version or public PR in this delivery. Sending changes and media policy are documented separately.

## Exact controller and protection

The supplied controller equations use a -20 dBFS robust speech target, -12..+18 dB learned range, +1.5/-3 dB per accepted speech second, probability >=0.95, 12 adjacent 10ms speech frames, 200ms estimate updates, a 5-second accepted-speech energy window, 1-second minimum estimate, and 20% trimming at each end. Tentative short runs do not enter the window. The initial 12 qualified frames are accepted retroactively. Positive gain obeys the -42 dBFS pre-manual noise budget, 120ms speech hold, and 120ms release; gain application rises with a 30ms exponential coefficient. Learned gain persists over pauses, while applied positive gain returns to unity. Negative gain persists. No wall-clock timer manufactures accepted speech or settled state.

The current chain is auto gain → per-person manual gain → fast downward protection and route sample limiter → sum → master gain → final bus sample limiter. It replaces the old 100ms RMS compressor with a linked, downward-only detector inside the route limiter: -15dBFS detector threshold, 0.1ms exponential energy coefficient, instantaneous peak/4 crest guard, immediate gain decrease, 100ms upward release, no makeup. This protection does not wait for VAD, identity binding or an RMS window to fill. Microphone role activates it through a k-rate AudioParam, including the initial worklet parameter values. It is not a promised hard RMS ceiling or a loudness metric. The strict Signalsmith-derived sample limiters each retain 3ms lookahead and -3dBFS ceiling. These are sample-peak limits, not true-peak or hearing safety guarantees. Source clipping cannot be reconstructed. No new gain follows the bus limiter.

`streamSources[id].gain` now means per-person manual gain only and starts at unity. Embedders must stop multiplying it by the global output gain. `useSpeakers` applies `audio.outputVolume` linearly as 0..200% → 0..2 on the summed bus, before final protection; initial route attachment applies master/mute before connecting audio. Changing master never changes pre-auto measurements or target and never overwrites per-person gains. At high manual/master settings protection can attenuate peaks; automatic gain does not compensate for a lower master.

Stereo microphones are measured using the arithmetic mean of the first two input channels, with linked gain applied to both channels. Ordinary mono/upmixed microphones match the supplied scalar processor equations. Antiphase stereo may cancel the analyzer measurement; independent per-channel route/bus peak limiting still works. Nonfinite input is zeroed; FloatS16 analyzer input is clamped to [-32768,32767] after exactly one normalized-to-S16 conversion. The gain energy measurement uses finite, unclamped source samples. This sanitation is an adapter boundary, not reconstruction of clipped audio.

## Analyzer provenance and real-time lifetime

The embedded 91,173-byte analyzer has SHA256 `21b6eb801901c5250215ff6a29b83471b13cdf45b69ba3fe438770b391a1d95b`. It is the verified supplied official WebRTC M131 / freedesktop audio-processing 2.1 RNN feature extractor, pretrained VAD, speech/noise estimator and resampler subset, built using Emscripten 4.0.20. Its upstream DSP source is unmodified. `third-party/receive-rnn` retains the wrapper/build scripts, pinned source archives, hashes, input attribution and all supplied notices. The app's AGPL license and Signalsmith MIT notice remain separate.

Receive processors in each AudioWorklet scope share one analyzer instance and one fixed 16MiB memory, with up to 32 separately generated handles. This does not describe sending RNNoise or other modules' memory. A microphone obtains a handle only when enabled, bound, and unmuted. Unknown/screen roles and unbound microphones never boost. They continue playing; screen/unknown bypass the compressor, while bound or unbound microphones retain independent compression and route/bus protection. A 33rd eligible stream reports `analyzer_unavailable` and safely uses unity auto gain plus compression/limiters; low-frequency control polling retries allocation after capacity becomes available.

Handles are created/destroyed in constructor or control-port handlers, never in `process()`. Processing uses fixed typed buffers and reused WASM views; there are no explicit per-frame JavaScript objects, promises, logs or messages. TypedArray sorting still has engine-internal implementation costs; this is not a claim of zero VM allocations. Telemetry objects are created only in the control handler. Reset reuses controller arrays. Disposal releases each handle and removes the registry entry; after the last route the shared runtime reference is released.

Supported context rates are integer 8..48kHz divisible by 100, including 44.1kHz. Other rates, including 96kHz, explicitly disable automatic gain with `unsupported_sample_rate`, retain microphone compression/limiters, and do not change devices or secretly resample. `noiseDb` being finite means the estimator is available, not ground truth. Historical speech-level confidence is never used as current VAD or noise confidence.

## Identity and authoritative local telemetry

`ReceiveStreamControl.setIdentity(identity | undefined)` accepts `{participantId,receiverId,trackId,generation}`. Use authenticated server identity, a stable local physical-route ID, actual audio track ID and monotonic replacement/reconnect generation. Aliases of one physical cleanup share one binding; multiple real tracks have different receiver IDs. Screen role takes priority when the client detects ambiguity. Setting identity does not change manual volume.

`useSpeakers().receiveAutoLevels` is a full authoritative `ReceiveAutoLevelBatch` with schemaVersion 1. It runs locally at 5Hz and never broadcasts through the SFU. Missing entries mean bindings have been removed. Lifecycle invalidation is immediate and has a higher public sequence within its generation. DSP-internal sequence and control revision reject stale processing/configuration data; public sequence remains monotonic over processor recovery. Old bus instances and old generations are rejected. Identity removal and route disposal clear old values. A null gain means unavailable, never a fabricated green zero. Subscriptions immediately receive the current batch.

`learnedAutoGainDb` is retained controller state; `appliedAutoGainDb` is the actual pre-manual coefficient, and may differ during pauses or prior restoration. `compressionGainReductionDb` reports the current post-manual fast protection coefficient separately, not the strict sample limiter's gain. `speechLevelDbfs` is the current robust speech RMS estimate, never LUFS. `settled` requires a full five-second current speech window, completed prior restoration and <=0.5dB target error for two accepted speech seconds; noise/range limitations instead report `limited`. `estimatorReliability` names current accepted-window evidence (provisional/established/invalid), not calibrated confidence. No speech perception or listening quality has been certified.

## Safe local historical priors

`ReceiveLevelPrior`, `RECEIVE_LEVEL_PRIOR_SCHEMA`, `validateReceiveLevelPrior` and `exportReceiveLevelPrior` are exported. The scalar schema is `{schemaVersion:1, processorSchema:"gryt-receive-level-v2", learnedGainDb, speechLevelDbfs, effectiveSpeechSeconds, lastVerifiedUnixMs}`. No samples, transient compressor state, current stream identity or device floor are serialized.

`receiveCleanup.setPrior(prior | undefined, expectedIdentity)` validates and copies scalars and queues only for the exact current participant/receiver/track/generation. Its boolean means queued, not that DSP has applied it. It rejects stale identities, invalid data and already observed current accepted speech. The processor also refuses delayed imports once it has accepted fresh speech. New identity/unbind clears the pending prior. Recovery can reapply the same pending history only to the same binding and always uses the safe restoration path.

An imported prior preserves historical learned gain, but starts actual requested gain within -6..+3dB and smooths its application. It adds no accepted seconds, energies or established evidence. Positive gain still needs fresh VAD/noise evidence and releases during silence. After at least one second of current robust speech, a >6dB level change rejects the history and restarts learned gain within the safe cap; otherwise the actual cap approaches learned gain at +1.5/-3dB per accepted speech second. `priorRestoring` and `priorRejected` expose these states. History cannot manufacture settled state.

`exportReceiveLevelPrior(snapshot, nowUnixMs)` requires five seconds of current established speech, recent accepted speech within one audio second, completed restoration, and learned gain within 0.5dB of its current bounded target. `lastAcceptedSpeechAudioTimeSeconds` records the audio block end in which real acceptance advanced, not a wall timer. The client must additionally require `acceptedSpeechSeconds` to advance for this exact binding before renewing lastVerified; repeated telemetry must not extend TTL. SDK does not own storage, account identity, server-instance identity, 30-day TTL, 500-entry LRU, clear actions or stale asynchronous write rejection. The client owns those boundaries and processor-schema isolation.

## Disable, suspend and fault behavior

Cold disabled routes use manual-only zero-added-delay paths. A previously warmed graph keeps its actual two-limiter delay when disabled, but adaptive gain, compression and limiting are bypassed; there is no forced -6dB attenuation on OFF. Queued protected samples retain protection until they exit their limiter delay. `receiveLevelingState.latencyMs` reports current added graph delay (6ms at 48kHz), even disabled; it excludes device, network and WebRTC delays.

Suspension invalidates telemetry and reports suspended. Resume uses the surviving graph; future actual measurements replace nulls. Context disposal removes timers, listeners and ports. Loader registration and analyzer compilation have independent caches, so compilation retry cannot register a processor name twice. A rejected addModule is retried. Analyzer traps and processor errors drop all adaptive processing, report degraded, and route through finite -6dB fallback gain plus retained route/bus sample clamps. Output remains connected. This emergency fallback is distinct from OFF. Retry uses bounded 1..30-second backoff, with fresh graph/handles and increasing public telemetry sequence. No real microphone or administrator profile is accessed by the validation scripts.

Global mute propagates to every route as an independent reason; global unmute preserves personal mute. Personal mute blocks its route and clears its own processor/delay state, while other routes and the mixed bus retain their state. Already mixed samples cannot be removed selectively: up to one bus lookahead (3ms at 48kHz) of that person's previously queued contribution may still emerge, including after a shorter mute/unmute. This is the existing playback-delay boundary, not replay from retained route state. Personal mute never resets the shared bus or adds a dropout for other participants. Device/WebRTC output buffers likewise cannot be recalled.

## Reproduction and limits

Run `npm run build`, `npm run check-receive-longterm`, `npm run check-receive-recovery`, `node scripts/check-receive-prior.mjs` and `node scripts/check-receive-prior-headless.mjs <playwright module path>`, and package checks. The real-RNN checks use official public PCM; scalar controller checks are deterministic math tests, not human speech labels. Recovery tests use fake main-thread nodes and say so. Protection tests isolate a known normalized -20dBFS signal rising30dB, representing a -38dBFS source with learned+18 becoming -8; they do not replace the RNN with mock speech. Headless checks exercise the exact AudioWorklet program and production prior graph. They are not full comparisons with the previous compressor or human voice labels.

Important investigation failures: a new type-only import initially caused TypeScript to emit a CommonJS wrapper into the inline worklet; build checks now strip only type imports and reject module wrappers. Initial protection controlled by port messages lost an offline rendering race; it now uses constructor parameterData and k-rate AudioParams. Browser output parity is required because compilation alone missed both problems.

Node or offline elapsed time cannot prove real-time deadlines, inaudibility, absence of underruns, or game-load safety. The prior frozen 32-route timing evidence remains historical, including startup outliers; it does not certify this modified protection under a real game. Actual two-way calls, hardware device switching, gaming load and listening remain user acceptance tasks.
