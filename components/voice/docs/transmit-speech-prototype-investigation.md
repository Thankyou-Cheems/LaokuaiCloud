# Final publication speech activity prototype

This local prototype is retained for review and evidence. Its independent postgate analyzer architecture is provisional while the parent task evaluates a shared sending VAD for automatic noise gating. It does not implement an automatic noise gate or publish/deploy a package.

The library's `audio.transmitSpeechActivityEnabled` defaults to false. `audio.transmitEligible` must be the embedder's actual current speak permission; omitted means false. SFU supplies a separate connected flag only when its actual peer connection is connected and the registered microphone sender has the live enabled stable publication track. Cleanup, reconnect and peer state transitions invalidate activity. This avoids a useMicrophone/useSFU singleton dependency cycle.

`useMicrophone().transmitSpeechActivity` is always boolean. It is true only for trusted RNN speech while all final publication reasons permit sending. `transmitSpeechActivityState` separately reports `available` or `unavailable` and its reason. A blocked publication produces a known false even if analysis cannot proceed; disabled, unsupported native/rate, loading, processor failure and stale processing have explicit reasons. Consumers must not convert a state object to truthiness. Neither `isTransmitting`, input meters nor packet counts are speech classifiers.

The observation branch uses `createMediaStreamSource(TransmissionController.stream)` after the real final publication gate and acknowledged boundary. Its AudioWorklet output is always zero and reaches a zero gain sink, while original publication PCM never traverses the analyzer. This preserves the stable output track, processing chain, fresh-capture recovery barriers and both publication-over-raw selection guards. User/server mute, unheld PTT, Squad suppression/recovery/fault, disconnected publication, missing speak permission, ended microphone and no microphone handles clear the indicator. Events carry a control revision; late messages from a previous gate revision or older than 250ms of audio time are rejected. A 500ms watchdog makes stopped processors unavailable. A processor error cannot silently become available after mute/unmute; disable/re-enable recreates the observer.

The existing 91,173-byte official WebRTC RNN analyzer is reused unchanged, including its 44.1/48k resampler. One independent microphone WASM instance costs a fixed 16MiB heap; it is created only with the option enabled and a live microphone handle. It adds one analyzer pass, not one per remote route. The receive worklet's runtime is currently a separate module closure and is not automatically shared merely because both processors occupy one AudioWorklet scope. Sharing the runtime requires a common registration/module contract and separate generated microphone handles.

Each decision consumes an actual 10ms frame. Probability >=0.95 for three adjacent frames enters speech; ten unqualified frames release it. Exact digital silence clears activity after a full zero frame, regardless of residual RNN probability. Silence still passes through the model to age its history. These values are deliberately conservative evidence thresholds, not calibrated speech sensitivity or a promise to identify every whisper. No RMS threshold manufactures a speech decision. Unsupported sample rates report unavailable, without silently changing the device rate.

The frozen `gryt_reset()` allocates a replacement State and changes its input/output ABI pointers. It is called only in control handlers; views are reacquired afterward. Processing never resets/recreates handles and tests confirm no WASM allocation/free calls during the processing loop. Regular disposal sends destroy, closes ports and disconnects the silent branch. Genuine dead worklets relinquish their isolated runtime with the node; no claim of synchronous browser GC is made.

Reproduce with `npm run build`, `node scripts/generate-transmit-speech.mjs --check`, `node scripts/check-transmit-speech.mjs` and `node scripts/check-transmit-speech-headless.mjs <existing-vendor-node_modules>`. The latter uses isolated headless Chromium, `--mute-audio`, blocked real getUserMedia, loopback HTTP and BelowNormal priority. Its fault fixture adds a test-only processor throw, allowing an actual browser processorerror event. Real public PCM works at 44.1/48k; seeded broadband noise produced zero speech blocks in four seconds per rate. Measured exact-silence clearing was 20.32ms / 10.67ms in the Node chunking fixture. Node elapsed time is not a real-time deadline, hardware, game-load or listening certification. Public input attribution remains in `third-party/receive-rnn/fixtures`.

# Shared RNNoise automatic gate investigation (no implementation)

`@shiguredo/rnnoise-wasm` 2025.1.5 `DenoiseState.processFrame(frame): number` already returns real 0..1 VAD probability (`dist/rnnoise.js:742-754` / `dist/rnnoise.d.ts`). `rnnoiseWorker.ts:processFrame` discards it and replies only PCM plus generation. `NoiseSuppressor` (`src/types.ts`) has no speech listener. Capturing that probability requires no new model invocation. Capture finite pre-denoise RMS in the same frame, retain probability/RMS/generation/sequence next to each processed PCM item in `_outQ`, then advance metadata only as `_outFrame` actually leaves the worklet. Preserve queue dropping, reset ACK and fresh-frame ACK behavior. A separate worker result arriving early cannot itself light the indicator.

A pre-gate candidate is needed to reopen a closed automatic gate. Combining the aligned candidate with actual final publication eligibility and same-generation nonzero output evidence can yield one shared send activity source. It must be described as captured-frame VAD plus publication evidence; it is not a second classification of final PCM. A strict demand to run the algorithm on final postgate samples needs another analyzer pass or a separate handle in a shared runtime. A candidate from RNNoise's input is also not a probability classified on its denoised output.

Current RNNoise has hardcoded 480-sample frames and no 44.1k resampler/rate check. Reuse at 44.1k requires an explicit 48k resampling contract or unavailable status; the current postgate WebRTC RNN does correctly support 44.1k. When noise suppression is disabled, the RNNoise processor is absent. A shared design therefore needs an explicit always-on analysis/bypass contract or one common WebRTC RNN source, without secretly applying denoising when disabled.

For a future automatic floor, use only finite, high-confidence non-speech pre-gate frames; treat near-zero fill/muted/disconnected/suppressed/recovering frames as ineligible evidence. Slowly raise the floor, allow decay toward quieter environments, use open/close hysteresis and a release tail, and open promptly on actual speech evidence including low levels. Device changes, capture generation, input volume and any gain stage before measurement invalidate old floor evidence. Measuring pre-AGC avoids conflating a moving send AGC with environment noise; measuring after AGC requires gain-aware invalidation. Threshold calibration, startup behavior and sensitivity need real speech/noise fixtures before choosing constants. Receiving learned gain must never set the sending gate.

The existing manual gate is normalized smoothed dBFS: `noiseGateProcessor.ts` maps -100..-30dBFS to 0..100. Threshold 1 corresponds to -99.3dBFS for steady input, not 1% amplitude. `microphonePipeline.ts` connects `volumeGain` to input 1 before RNNoise for detection. Threshold 0 (including PTT) bypasses this noise gate. `web.ts` disables browser AEC, NS and AGC by default; own RNNoise, send AGC and compressor are optional. Browser echo cancellation must not be inferred from the configured value; actual device settings are a separate capability check.
