# Atomic voice move control protocol v1

Review corrections: committed activation uses the transaction's exact captured peer ID, with distinct retired state, never a room/user search. `move_remove` shares normal server authentication and transaction identity; it aborts pending or fences/removes the exact committed destination peer, retaining historical committed status with `removed:true`. It does not follow a new generation. Duplicate old commits cannot republish a removed or retired peer. Move-preservation audio-control speak gating applies only to peers activated through this protocol; ordinary peers retain existing behavior.

`move_refresh` authenticates the same immutable transaction and applies current caps/mute/deafen only if its captured committed peer/generation is still live, returning an ACK after the live claims and deafen state are updated. It rejects pending/removed/replacement peers. App committed authority awaits this refresh to repair old-source controls sent while the commit ACK travelled. Track-manager receiver retirement is durable across forwarders created after the membership swap and is released only after the old PC closes.

Base: official SFU `1617bf3d4d99b3030c8c095abb22bc303706527a`. This is a local implementation; production deployment and policy enablement require separate approval. Live seat/resource settings are unchanged.

Server controls `move_probe`, `move_prepare`, `move_status`, `move_commit`, `move_abort` return `move_result`. Commands carry `{command_id,request_id,server_id,server_password,user_id,source_room_id,destination_room_id,socket_id,nonce,expires_at_ms,capabilities,is_muted,is_deafened}`. Probe needs command_id/request_id/server_id/server_password only. Request identity/source/destination/socket/nonce is immutable; only approved caps/audio can refresh at commit. Unique command_id prevents a delayed older reply from resolving a later command for the same request_id.

Result is `{command_id,request_id,status,error?,source_room_id,destination_room_id,user_id}`. Status is supported/prepared/ready/committed/aborted/failed. No credential, join token or nonce is returned. Status and abort authenticate credentials even after a referenced room is removed.

Client join is `{event:"client_join",data:JSON.stringify({room_id,server_id,user_id,user_token,move_id:requestId})}`. Signed v2 token contains app_socket:<socket_id> and move:<request_id>:<nonce>. Omitting move_id from a staged token is rejected. Destination/user/nonce/current socket binding must match the prepared transaction.

Prepare verifies a unique actual source PC bound to the signed socket id; one reservation per server/user. Pending PC is not added to live room, seat or sync maps. Its claims initially deny all speech/share, and generic permission pushes cannot activate it. Direct staged offer contains only the fixed negotiated transceivers and no room tracks. Only Pion PeerConnectionStateConnected marks ready.

Commit rechecks source PC/member/socket identity and pending liveness, then synchronously fences source publishing and retired receiving before swapping room maps under the same manager lock used by authoritative sync. No fallible operation follows the fence inside the membership critical section. It activates current destination capabilities, mute and deafen before ACK. Closing old source follows the authoritative swap; that closure may reach the SDK before the app's ACK. Stale signaling snapshots cannot reopen retired receivers. Duplicate commit does not repeat the fence or change current grants.

Abort, pending disconnect and 30s expiry retain source and close pending. A genuine source disconnect is not fabricated back into the room. Terminal results stay queryable five minutes, with closed PC references released. Transaction state is in-memory: process restart loses it and PCs, so a missing/unknown reply is not proof of historical commit/abort. Server/SDK must query and preserve uncertainty.

`SFU_AUDIO_ONLY=true` is a separate default-off opt-in: reject every video/screen-audio/unknown transceiver slot regardless of legacy grants; only microphone slot 0 negotiated as audio is eligible for speak. Server must also deploy `VOICE_AUDIO_ONLY=true` to remove share grants at token/live-cap paths including Doctor. The allowed Opus microphone stream can carry software-created content; no server-side decoder/DSP/content detector exists here. Audio-only cannot be advertised as content identification.

Current mute/deafen are retained through transfer. Capability updates retain mute while allowing a later legitimate unmute to restore only presently granted speak. The same mute gate applies to existing server audio-control messages; production reviewers should include this enforcement in the policy approval.

Tests use synthetic credentials, local Pion/loopback RTP and ephemeral websocket harnesses. They cover invisible staging, real Connected readiness, media hold/fence, atomic sync under competing commit/abort, duplicate/result query, abort/expiry/source generation and source/pending failure, token misuse, command correlation and legacy audio-only rejection. No production endpoint, microphone, owner profile or real token is used.
