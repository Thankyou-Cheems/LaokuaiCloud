# Frozen native dependency and distribution review

This review covers the actual no-Npcap core/CLI from native source `dbaf04531024f4201e73ec0bc5ba6a7a6d8d3b49`, Cargo.lock `e3ee41507e7a8ef94470b70f4639140e67aadae646ada82dfd23b0beeb0e7fb2`, the locked Windows x64 seventeen-feature graph and the unchanged signed Wintun/WinDivert companions. It is a follow-up to application build freeze `83dd572fad7837c9716153b9cc2e58535db1b875`; it does not change that build's source, payload, gates or notices. The new text bundle is a later source input, not evidence that the in-progress candidate already contains it.

`native-license-review.json` records all 506 packages, original metadata, authors, source or registry checksum, potential distribution class, and hashes/origins of the actual license texts. `EASYTIER-THIRD-PARTY-LICENSES.txt` preserves the original notices and terms in a deduplicated UTF-8 compilation. Original text hashes refer to the source bytes before compilation. Neither file imports Cargo cache paths, profiles, credentials or research logs. Both are under the existing recursive `release/licenses` legal resource configuration for subsequent builds; actual inclusion must be checked against the resulting package.

The graph contains 388 normal, non-proc-macro reachable packages and 118 build/proc-macro-only packages. Reachability is a conservative inventory, not proof that every crate's objects survive linking. Build and proc-macro source may still be needed to rebuild the distributed work. No dependency was excluded merely to avoid a license obligation. Existing normal/build cached text hashes are verified against the build owner's immutable inventory. Registry archive byte verification is recorded individually; absence of a local archive is not represented as verification.

All 25 former top-level text omissions were examined. Twenty-three cases have original texts, explicit source notices or a referenced standard with an original dedication. `crc-catalog` uses `LICENSES/`, `plist` uses `LICENCE`, workspace/Git crates use repository-root texts, and other monorepo texts were recovered at their `.cargo_vcs_info` exact commits. The five encoding index tables have explicit source CC0 dedications, preserved alongside the [official CC0 terms](https://creativecommons.org/publicdomain/zero/1.0/legalcode.en). The protobuf BSD condition is preserved from all six original bundled `.proto` copyright/license headers, alongside Apache-2.0; it is not dropped from the `AND` expression.

Three publication provenance questions remain explicit:

- `encoding-utils@0.1.0` declares MIT and author `a632079`. Its published source and pinned repository `f029c6e1eec8153c4d06e872b3ca9a88d90db174` contain no author license/copyright text.
- `seahash@4.1.0` declares MIT and authors ticki/Tom Almeida. Its published source and pinned GitLab tree `94b632aeac099031c373599313d5b5f0acbbaec0` contain no author license/copyright text.
- `encoding_index_tests@0.1.4` declares CC0 but its source retains Kang Seonghoon's 2013–2015 copyright and refers to the rust-encoding family LICENSE.txt (MIT). Both the original header/family notice and CC0 terms are retained. This discrepancy is not silently normalized away.

The two MIT cases include an explicitly labelled [SPDX v3.25.0 standard reference](https://github.com/spdx/license-list-data/blob/v3.25.0/text/MIT.txt), their actual declared authors and metadata. Placeholder standard terms are not passed off as an author-issued license or fabricated copyright year. Before external delivery, settle the missing author-notice provenance and the encoding helper expression, or use a separately reviewed replacement dependency. No dependency replacement was made here. No author contact or legal approval is implied.
