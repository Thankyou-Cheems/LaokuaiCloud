# Receive correction display

The Voice package supplies receiver-local authoritative batches at 5 Hz. The client binds physical microphone routes using a JSON tuple of server host and actual server user ID, a unique receiver ID per physical cleanup, actual track ID and a monotonically increasing generation. Missing, ambiguous, screen and unbound routes show unknown / not measured. RMS, targets, manual GainNode values and graph active are not gain telemetry. The ring neither enables nor adjusts DSP.

The main ring represents learnedAutoGainDb; details separately present appliedAutoGainDb and localized limitation reasons with unchanged diagnostic codes. Manual volume and compressor or limiter reduction are excluded. A measured zero is distinct from a missing measurement. The visual scale is -12/+18 dB, with text showing the original measured value even outside that range. Controller learning policy belongs entirely to Voice.

Aliases aggregate by physical cleanup with screen priority. Ordinary membership updates preserve identities; track replacement and reconnect create new generations. Measurements require an exact identity match, finite or explicitly null values and monotonically increasing sequences. Same-sequence unavailable/null clears are accepted defensively, but cannot be undone by a duplicate measurement. Missing routes in a full batch clear immediately; clearing one route preserves other routes. Client tests cover this external SDK boundary and the real rendered display using synthetic measurements. No production protocol change, microphone capture or acoustic acceptance is implied.
