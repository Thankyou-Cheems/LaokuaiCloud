# Community EasyTier main integration

This change implements the Electron main lifecycle, Windows sidecar adapter ports, trusted preload IPC and the member UI v1 projection. It does not activate a network. `main.ts` deliberately constructs `EasyTierCommunityManager(null, emit)`. Replace that null only after the native Windows transport, owned handle/job, driver/permission and exact artifact acceptance gates have passed. There is no renderer API for injecting an executable, config, peer URL, secret, process ID or approval object.

Apply UI owner commit `de27c593b96e8265d9dda1280d6604e9d755a462` before this patch: `easyTierMemberAdapter.ts` and the state type import its unchanged `src/lib/memberLanStatus.ts`. The main patch does not redefine that contract or edit member UI/SDK behavior. Verification used an exact local copy of that dependency, excluded from this patch.

## Renderer contract

`window.easyTierCommunity` exposes `connect({serverId, leaseId})`, `disconnect({serverId, leaseId})`, `disconnectCommunity(serverId)`, `setEnabled(boolean)`, `getState(serverId)` and `onState(callback) -> unsubscribe`. State is `{serverId, generation, phase, reason, virtualIp, lanSnapshot}`. `lanSnapshot` is the UI owner's `LanCommunitySnapshot | null`, with canonical server scope and independent local observer/member bindings; the UI's voice reading stays explicitly unknown. The room ID is absent.

The authenticated community/server integration acquires a stable consumer lease after joining that server. Repeated acquisition of the same lease is idempotent. Multiple consumers retain one community instance until the last release. Voice room join/switch/leave only changes media. Explicit community disconnection clears its leases; disabling LAN releases all instances while preserving references for a later enable. Application exit terminates only the original app-owned core handle. Community release deletes only its instance, preserving other communities in the shared core. No Tencent process is added by this client adapter.

Leases are not persisted in a real profile. Startup defaults disabled. Successful startup is independent of account identity and existing SFU voice operation. Error states carry enumerated reasons only. No main identity-store, SDK media or SFU references are imported. No background restart of a shared core occurs.

## Windows native integration ports

`WindowsEasyTierRuntime` implements one shared owned core with per-community plans. Provisioning must resolve the stable authenticated server ID to a unique network name and opaque config reference. Same network name with a different secret is rejected locally rather than treated as a separate network. Instance IDs are also reserved before asynchronous startup. Provisioning and credential lifetime stay at the secure main/native boundary.

`startOwnedCore()` must launch an isolated app-owned process with loopback-only RPC, no inherited ET environment overrides or global config, and capture its original process handle/job. Suppress/discard unsanitized core stdout/stderr and native errors; upstream startup output can contain configuration and physical endpoints. `terminateOwned()` must use that captured ownership; no image-name kill, user-process attach or reopening a PID. `runInstance()` must dispatch scoped `WebClientService.RunNetworkInstance` without overwrite and drain its definitive ACK. `waitForRunning()` must confirm the scoped instance has reached running readiness. An ACK alone is insufficient. Deletion must use only the owned ID, then confirm it is absent. Never use `RetainNetworkInstance`, which can delete every other instance.

v2.7 mutations spawn independent tasks. Consumer cancellation stops waiting/UI ownership, but does not establish rollback of a dispatched server task. The adapter drains a started mutation; when its outcome is indeterminate, it retains the plan and reports cleanup failure until `reconcileMutation()` can independently prove resolution. A premature absent instance list alone is not proof. Per-community lanes and generations prevent a replacement from overlapping its canceled predecessor. Watchdogs settle UI operations even if a native promise never returns; the native transport must also have its own bounded operations.

Stock core uses its own bidirectional protobuf RPC, not HTTP/gRPC. FFI `call_json_rpc` is not a core.exe HTTP JSON endpoint. CLI JSON plus explicit instance ID is useful for scoped status, not proof of a dynamic mutation transport. The candidate must explicitly bind `127.0.0.1:<port>`: a port-only value binds `0.0.0.0`. Loopback/CIDR restrictions are not local-user authentication; an elevated stock core cannot be described as controllable only by Electron. This known local RPC exposure must be reviewed at activation. The trusted renderer IPC check protects the Electron boundary only. This stage creates no privileged service and does not switch to FFI/DLL/mini/WASM.

`bindings()` must verify an authenticated server/user/device/peer binding, including server, instance, generation and expiration, before returning it. Possession of an ET network secret is not user authentication. Signed enrollment, binding timestamps and verified relay roles must not be synthesized from online presence, nicknames, addresses or route visibility. Normalize source timestamps to Unix milliseconds for the UI and use monotonic time for local expiration/cancel handling.

The adapter reads scoped `CollectNetworkInfo`. A physical-direct label requires a separately verified current data-forwarding decision matching the route candidate for the verified latency-first policy, the selected default connection, an open local-to-remote connection, a direct-connection ID and a recognized physical tunnel. The [v2.7 forwarding selection](https://github.com/EasyTier/EasyTier/blob/8b7f1f0196edb5b580829ed5f135050fb5853478/easytier-core/src/peers/peer_manager.rs) can choose a present peer or foreign-network path depending on the packet policy; a route table alone is insufficient. Virtual IP, one hop, host ICE candidate or merely having an unused direct tunnel is insufficient. Relay role remains unknown until the actual next-hop's server/member role is independently verified. Bare `PeerConnStats.latency_us` has no independent source timestamp, so it is not emitted as fresh RTT. Optional `observations()` can supply verified forwarding decisions and separately scoped timestamped local RTT; both default to unknown. There is no SFU/ICE RTT reuse. The current adapter emits RTT only when a selected physical-direct path and matching fresh endpoint observation both exist.

The unchanged UI v1 contract independently expires snapshot, observer/member binding, enrollment, route and RTT after 10 seconds. The host must continue advancing `lanNowMs` while telemetry is idle. Main polls every 2 seconds after registration, without reference to a voice room. A failed poll clears telemetry while preserving the LAN session. This does not imply zero traffic outside voice: ET heartbeat/discovery and LAN game traffic can continue.

## Pinned source and asset evidence

The user selected **v2.7.0 pre-release**, not floating latest. `electron/easyTierTarget.ts` records tag `v2.7.0`, commit `8b7f1f0196edb5b580829ed5f135050fb5853478` and Windows x86_64 archive `easytier-windows-x86_64-v2.7.0.zip`, 39,616,733 bytes, SHA256 `790fd9be347b00753570ac2b65f874a591ede9427603fe34e74a86b2b084847f`. These are [official release API metadata](https://api.github.com/repos/EasyTier/EasyTier/releases/tags/v2.7.0), obtained on 2026-10-11. This task did not download or independently hash the archive: direct shell DNS was unavailable. `targetVerified` must remain false until the native/packaging owner verifies the local bytes and executable. Version, commit and archive digest mismatches cannot activate the adapter.

Source capability is distinct from binary/transport acceptance:

- [v2.7 core startup](https://github.com/EasyTier/EasyTier/blob/8b7f1f0196edb5b580829ed5f135050fb5853478/easytier/src/core.rs) keeps config-dir/multi-config startup and creates the native instance manager.
- [ProcessManagement RPC implementation](https://github.com/EasyTier/EasyTier/blob/8b7f1f0196edb5b580829ed5f135050fb5853478/easytier-core/src/management/full/process_rpc.rs) implements dynamic run/delete/list and scoped collection; [registration](https://github.com/EasyTier/EasyTier/blob/8b7f1f0196edb5b580829ed5f135050fb5853478/easytier-core/src/management/full/mod.rs) exposes WebClientService. The [native RPC server](https://github.com/EasyTier/EasyTier/blob/8b7f1f0196edb5b580829ed5f135050fb5853478/easytier/src/rpc_service/api.rs) gates full management by the management feature, included in [default features](https://github.com/EasyTier/EasyTier/blob/8b7f1f0196edb5b580829ed5f135050fb5853478/easytier/Cargo.toml). Dynamic runtime RPC is supported by source; this patch does not claim the unimplemented native transport has passed operational acceptance.
- [Management protobuf](https://github.com/EasyTier/EasyTier/blob/8b7f1f0196edb5b580829ed5f135050fb5853478/easytier-proto/proto/api_manage.proto) preserves running info and scoped lifecycle RPC. [Instance protobuf](https://github.com/EasyTier/EasyTier/blob/8b7f1f0196edb5b580829ed5f135050fb5853478/easytier-proto/proto/api_instance.proto) supplies next-hop, latency-first next-hop, default/direct connection identifiers and latency_us; there is no per-latency measurement timestamp.
- [v2.7 Windows broadcast filter and regression](https://github.com/EasyTier/EasyTier/blob/8b7f1f0196edb5b580829ed5f135050fb5853478/easytier/src/instance/windows_udp_broadcast.rs) exclude outbound loopback copies and preserve legitimate retransmissions. This matches the effective fix in the prior `NATIVE_GAME_RESULT.md` / old v2.6.4~broadcastfix source. No old broadcast patch is stacked onto the official 2.7 candidate.
- [v2.6.4 core](https://github.com/EasyTier/EasyTier/blob/v2.6.4/easytier/src/core.rs), [multi-instance CLI test](https://github.com/EasyTier/EasyTier/blob/v2.6.4/script/test-cli-multi-instance.sh), [registered RPC](https://github.com/EasyTier/EasyTier/blob/v2.6.4/easytier/src/rpc_service/api.rs) and [dynamic implementation](https://github.com/EasyTier/EasyTier/blob/v2.6.4/easytier/src/rpc_service/instance_manage.rs) already supported single-process multiple instances. The old source remains useful evidence, not the new target.

The [2.7 release notes](https://github.com/EasyTier/EasyTier/releases/tag/v2.7.0) describe legacy QUIC fallback and features that benefit fully only when both ends upgrade. That is compatibility intent, not a proven 2.7 client / 2.6.4 server matrix. No such live pairing was run here. The dedicated operations owner's Tencent public-node result should update the integration matrix; the private server remains outside this patch. Secure-mode identity/auth, secure relay and ETQ1 guarantees require exact negotiated capability verification, not a version comparison alone. No secure-mode policy or credentials were changed. Config-server full-URL, old WireGuard portal and Web DB migrations are not exercised by these ports and are not introduced into this client stage.

Bootstrap is configurable through opaque main-only provider references, defaulting to existing owned entries only. No public entry is hardcoded or connected. `external-node` appends a normal peer; it is not discovery-only. Relay whitelist belongs to the node enforcing it; it cannot control someone else's public node. Route avoidance is not a strict payload prohibition. Public discovery-only requires separate verified capability/policy and remains disabled.

## Verification and remaining activation gates

Run `node scripts/check-community-easytier.mjs` and `node scripts/check-community-easytier-types.mjs` after the UI dependency is present. The 36 pure scenarios mock all runtime ports, deny unmocked imports, and use deterministic watchdogs; no ET core, driver, helper, socket, Docker or profile is accessed. New main modules passed a strict targeted TypeScript no-emit check; edited main/preload entrypoints passed syntax checks. Full application semantic typecheck/build, packaged executable verification, native transport/provisioning/binding/forwarding verification, real ET/game/media behavior and exact-handle process cleanup on Windows remain for the integration/native owners. No pushes, deployments, routes, firewall changes or live service actions were performed.
