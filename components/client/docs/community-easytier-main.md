# Community EasyTier main integration

This change implements the Electron main lifecycle, a production Windows sidecar launcher and official CLI reader, trusted preload IPC, renderer community membership subscriptions, and the member UI v1 projection. `main.ts` injects the real `WindowsEasyTierCliRuntime` through `createWindowsEasyTierProduction`; the isolated i18n test package keeps a null runtime. Constructing this adapter performs no I/O or activation. This task only wrote source, prepared static assets and ran pure/type checks; it did not activate a network. The renderer cannot inject an executable, config, peer URL, secret, PID or approval object.

## Production path and limits

`easyTierExistingConfiguration.ts` reads the product-owned `userData/community-lan/activation.json` receipt and hash-pinned existing files under its `configs` directory. It resolves real paths to reject symlink escape and arbitrary profiles. The receipt requires schemaVersion 1, approved, driverPermissionApproved and localManagementApproved, with unique community IDs, instance UUIDs and network names. Each community reference is `{serverId, instanceId, networkName, configFile, configSha256, bootstrap: "product-owned"}`. The provisioner must review/pin the complete config, including its product-owned bootstrap endpoints. Neither the receipt nor renderer has a secret field or public fallback. These fields are internal product provisioning data, never a novice configuration form. This task did not create or read a real receipt/config.

Connect checks that approved reference, inspects the actual Windows token without elevation, verifies the release-owned downstream manifest and all five runtime files, spawns exactly one owned core from the existing config, and reads the official CLI with explicit instance UUID until a private virtual IPv4 appears. It strips ET/RUST logging overrides, uses `--disable-env-parsing`, binds explicit `127.0.0.1:<port>` and a `127.0.0.1/32` whitelist, disables console/file logging and discards raw output except bounded private stop/resource receipts. Captured CLI node-info JSON is reduced to peer ID/private virtual IP; config/public endpoints never reach renderer or logs. CLI calls are bounded at two seconds, manager operations at eight seconds. Canceled/late startup is closed; ownership remains retained if exit cannot be confirmed. Exit/update/session-end cleanup uses captured child handles only, with no attach, PID lookup, kill-by-name, user ET shutdown, service install or automatic elevation.

The official 2.7 CLI has **no dynamic instance Run/Delete command**. This injected path supports one active community per client, returning `multi-community-unavailable` for a second community without launching another core or restarting an active game. Leaving that community or disabling LAN terminates its sole owned sidecar. Full renderer membership snapshots drain departing sessions before replacement, retain LAN through renderer remount/signaling reconnect, and reconcile removed memberships after reload. Voice rooms never enter this lifecycle. The separate multi-instance `WindowsEasyTierRuntime` remains a port-based adapter and is not injected; custom protobuf mutation transport is still pending. This is a client CLI limitation, not an upstream single-process/single-network assumption.

Missing approved configuration gives `configuration-required`; missing activation/current token permission gives `needs-permission`. The UI explains the action and leaves the existing SFU voice path available. Stock sidecar currently requires an administrator application token; installing drivers alone does not establish normal-user operation. There is no UAC bypass. Stock loopback RPC lacks Windows user authentication, so `localManagementApproved` is an explicit remaining exposure acceptance gate, not a security boundary. No official console, privileged service, helper, identity issuance backend or root-secret system is deployed here. A service owner still needs an authorized mechanism to install existing community references at this main-only boundary: novice first-run provisioning is not yet complete. Missing authenticated user/peer bindings and timestamped forwarding/RTT evidence keeps member readings unknown without blocking basic LAN.

`node scripts/prepare-community-easytier.mjs --archive <official-archive>` remains a static development helper for the official five files. Production preparation accepts only a release-owned `laokuai-build.json` with the reviewed source-patch digest and a separately measured downstream core hash. Gitowner must pair that compiled core/manifest with the pinned official CLI, Packet.dll, WinDivert64.sys and wintun.dll. Windows packaging includes those five files plus the manifest and excludes both official console executables. Production `prepareRuntime()` verifies/copies this bundle into a cache keyed by downstream core hash; it does not download an official fallback. The template's null core hash intentionally prevents activation before build/review. All hashes are checked again before launch.

Apply UI owner commit `de27c593b96e8265d9dda1280d6604e9d755a462` before this patch: `easyTierMemberAdapter.ts` and the state type import its unchanged `src/lib/memberLanStatus.ts`. The main patch does not redefine that contract or edit member UI/SDK behavior. Verification used an exact local copy of that dependency, excluded from this patch.

## Renderer contract

`window.easyTierCommunity` exposes `connect({serverId, leaseId})`, `disconnect({serverId, leaseId})`, `disconnectCommunity(serverId)`, `setEnabled(boolean)`, `getState(serverId)`, `syncMemberships(serverIds)`, `prepareRuntime()` and `onState(callback) -> unsubscribe`. State is `{serverId, generation, phase, reason, virtualIp, lanSnapshot}`. `lanSnapshot` is the UI owner's `LanCommunitySnapshot | null`; voice readings remain unknown. Room ID is absent. Renderer subscribes from saved memberships with stable serverId, excluding pending approval entries, and offers local status, enable/disable, prepare and retry controls without any SFU call.

Community integration acquires a stable lease after joining a server. Repeated acquisition is idempotent; multiple consumers retain one session until the last release. Voice rooms only change media. Community disconnection clears its leases; disabling LAN releases sessions while preserving references for re-enable. Exit terminates the original owned child only. The injected CLI adapter terminates its sole community core; the optional dynamic adapter deletes only its scoped instance while preserving others. No Tencent process is added.

Main constructs disabled. Renderer enables LAN unless the person previously selected off; main-only configuration and permission approvals remain required. Leases stay in memory with complete snapshots for reload reconciliation. LAN failures neither reset identity nor block existing SFU voice. Errors contain enumerated reasons only. No main identity-store/SDK-media/SFU import or background shared-core restart occurs.

## Optional dynamic RPC ports (not the production CLI path)

`WindowsEasyTierRuntime` implements one shared owned core with per-community plans. Provisioning must resolve the stable authenticated server ID to a unique network name and opaque config reference. Same network name with a different secret is rejected locally rather than treated as a separate network. Instance IDs are also reserved before asynchronous startup. Provisioning and credential lifetime stay at the secure main/native boundary.

`startOwnedCore()` must launch an isolated app-owned process with loopback-only RPC, no inherited ET environment overrides or global config, and capture its original process handle/job. Suppress/discard unsanitized core stdout/stderr and native errors; upstream startup output can contain configuration and physical endpoints. `terminateOwned()` must use that captured ownership; no image-name kill, user-process attach or reopening a PID. `runInstance()` must dispatch scoped `WebClientService.RunNetworkInstance` without overwrite and drain its definitive ACK. `waitForRunning()` must confirm the scoped instance has reached running readiness. An ACK alone is insufficient. Deletion must use only the owned ID, then confirm it is absent. Never use `RetainNetworkInstance`, which can delete every other instance.

v2.7 mutations spawn independent tasks. Consumer cancellation stops waiting/UI ownership, but does not establish rollback of a dispatched server task. The adapter drains a started mutation; when its outcome is indeterminate, it retains the plan and reports cleanup failure until `reconcileMutation()` can independently prove resolution. A premature absent instance list alone is not proof. Per-community lanes and generations prevent a replacement from overlapping its canceled predecessor. Watchdogs settle UI operations even if a native promise never returns; the native transport must also have its own bounded operations.

Stock core uses its own bidirectional protobuf RPC, not HTTP/gRPC. FFI `call_json_rpc` is not a core.exe HTTP JSON endpoint. CLI JSON plus explicit instance ID is useful for scoped status, not proof of a dynamic mutation transport. The candidate must explicitly bind `127.0.0.1:<port>`: a port-only value binds `0.0.0.0`. Loopback/CIDR restrictions are not local-user authentication; an elevated stock core cannot be described as controllable only by Electron. This known local RPC exposure must be reviewed at activation. The trusted renderer IPC check protects the Electron boundary only. This stage creates no privileged service and does not switch to FFI/DLL/mini/WASM.

`bindings()` must verify an authenticated server/user/device/peer binding, including server, instance, generation and expiration, before returning it. Possession of an ET network secret is not user authentication. Signed enrollment, binding timestamps and verified relay roles must not be synthesized from online presence, nicknames, addresses or route visibility. Normalize source timestamps to Unix milliseconds for the UI and use monotonic time for local expiration/cancel handling.

The adapter reads scoped `CollectNetworkInfo`. A physical-direct label requires a separately verified current data-forwarding decision matching the route candidate for the verified latency-first policy, the selected default connection, an open local-to-remote connection, a direct-connection ID and a recognized physical tunnel. The [v2.7 forwarding selection](https://github.com/EasyTier/EasyTier/blob/8b7f1f0196edb5b580829ed5f135050fb5853478/easytier-core/src/peers/peer_manager.rs) can choose a present peer or foreign-network path depending on the packet policy; a route table alone is insufficient. Virtual IP, one hop, host ICE candidate or merely having an unused direct tunnel is insufficient. Relay role remains unknown until the actual next-hop's server/member role is independently verified. Bare `PeerConnStats.latency_us` has no independent source timestamp, so it is not emitted as fresh RTT. Optional `observations()` can supply verified forwarding decisions and separately scoped timestamped local RTT; both default to unknown. There is no SFU/ICE RTT reuse. The current adapter emits RTT only when a selected physical-direct path and matching fresh endpoint observation both exist.

The unchanged UI v1 contract independently expires snapshot, observer/member binding, enrollment, route and RTT after 10 seconds. The host must continue advancing `lanNowMs` while telemetry is idle. Main polls every 2 seconds after registration, without reference to a voice room. A failed poll clears telemetry while preserving the LAN session. This does not imply zero traffic outside voice: ET heartbeat/discovery and LAN game traffic can continue.

## Downstream Windows stop / host-policy review update

The injected production adapter now requires **2.7.0-laokuai** from a release-owned `laokuai-build.json`. It rejects the official core executable's measured hash and any manifest lacking the exact reviewed source-patch digest, externally-managed host policy or owned-stop protocol v1. Preparing the official archive remains a static development helper; it cannot activate production TUN. No downstream binary is built in this stage, so the product gate remains closed until Gitowner supplies its separately measured artifact.

The source patch against upstream `8b7f1f0196edb5b580829ed5f135050fb5853478` disables global NetworkList cleanup, automatic firewall installation/removal and profile Category changes under its hardcoded externally-managed policy. It requests a fresh TUN GUID, checks aliases and reports GUID/LUID/ifIndex. Task-6 review found that the pinned TUN dependency can still open an existing adapter before the GUID check; this blocks payload approval pending the native owner's create-only fix (see `components/easytier/REVIEW.md` in the integration root). These main-only identifiers remain diagnostics, never saved cleanup authority.

Production close now writes the private stdin stop request and closes that pipe. Patched core awaits `CoreInstance::stop()` without deleting persistent configuration, then sends its stop receipt. Only after 4 seconds may Electron force its exact owned child handle; after 6 seconds without exit, ownership remains pending and `cleanup-failed` is raised. Stop is idempotent. Ordinary app quit/update waits for drain. Windows session end begins stop synchronously; OS deadlines can still preempt the drain. Forced/unconfirmed exits and reported interfaces require residual review, with diagnostic-only receipts persisted to the product root on ordinary quit. No process name scans or user GUI termination occur.

The static source checks and targeted Rust syntax formatting passed; the Windows Rust build, downstream executable hash, native stop/Drop behavior and real TUN coexistence remain unverified. The custom dynamic adapter remains gated and must not bind its `deleteInstance` placeholder blindly to stock `DeleteNetworkInstance`: that RPC may delete persistent config. A future dynamic transport needs a separately accepted non-destructive per-instance stop contract. No new RPC/FFI layer is added here.
