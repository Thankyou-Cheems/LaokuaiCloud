# .17 候选：成员节点状态、Ping 规则与语音连续性

日期：2026-10-14。基线为桌面 .16。本文描述候选改动，不表示已更新桌面、
生产 Gryt 或完成双人验收。用户要求暂缓降噪/音质默认值调查。

## 触发与修复范围

现场见 [调查记录](LIVE16-AUDIO-LAN-DIAGNOSIS-20261014.md)。朋友到本机 Ping
4/4 成功，本机主动 Ping 朋友超时。双方自己的节点显示已入网，对方却只显示
地址已分配。语音日志则出现新鲜解码与路径 unknown 共存后回退 SFU。

这三项不是一个故障：

1. 原有目录只给远端地址，没有接入远端节点身份观测。新 Gryt `directory`
   的 `includeBindings:true` 扩展按当前授权和 credential/peer/IP 关联验证节点，
   一次请求共用一份管理端图，不向客户端暴露 credential key。
   观测最多 5 秒有效；客户端每 2 秒刷新，HTTP 等待、缓存及冻结 UI 均不能
   延长有效期。旧服务只在明确不支持扩展时退回原目录，旧客户端响应不变。
   成员卡区分“节点已连接”“ET 路由可见”和实际直连/中继；没有测得的 RTT
   不填值。节点可见不宣称游戏端口或 Ping 已通。
2. 原有两个程序防火墙规则不覆盖系统 ICMP Echo responder。新增独立账本，
   以本应用活 core 的 GUID/LUID/index 收据及已认证社区 IP/CIDR 为依据。
   native helper 验证映射和实际地址后，才建立单接口、单本地地址、社区源网段、
   仅 ICMPv4 type 8 的规则。它不放开全接口服务或游戏全部端口。
   NIC 身份确认后 IP 尚未就绪允许最多三次准备，间隔 250 ms；身份冲突不重试。
   准备失败记录原因，游戏 LAN 不因此重启或退出。
   正常退出先精确移除规则，再关闭网卡；显式清理仅处理该账本记录。
   外来/属性已改/重复名称/接口字段丢失的规则保留并报失败，不删除历史 ET 规则。
3. 活跃 P2P 在仍有当前音轨新增 packet/sample 时，允许最多 1500 ms 的有限
   selected-pair 统计缺项。首次准入不放宽，持续缺项、明确失败或停流仍回退。
   不把 unknown 显示成直连，不更改 ET 生命周期。详细红绿回归见
   [语音记录](PEER-PATH-GAP17-20261014.md)。现场统计为何缺失仍未确定。

## 验证中发现的实际 Windows 差异

未注册的 `HNetCfg.FWRule` 内存对象 setter/readback 实测：单 IPv4 回读为
`IPv4/255.255.255.255`，`/24` 网段回读为点分掩码。已据此修正严格等价比较，
仍拒绝单主机规则被改成宽网段、列表或通配符。探针没有创建防火墙策略对象、
没有注册规则。此前只用 fake COM 字符串会漏掉此差异，故不能据 mock 通过声称
Windows 安装或双向 Ping 已验收。

整合核心检查首次在退出 fixture 失败：新增显式 TUN 规则清理端口未注入，导致
fixture 把 ReferenceError 当成清理失败。已补入端口并断言仅在显式清理时调用，
不删除原失败断言。最终检查结果另记，不能用早先局部通过代替。

## 交付和实测边界

远端节点状态需要新版客户端和新版 Gryt；本候选不要求更换 SFU、EasyTier
core 或管理代理。Ping 规则在升级后的各自客户端运行时准备，因此只升级本机
不能证明朋友侧入站 Ping 已恢复。当前运行桌面和用户数据没有被本次开发修改。

后续真实验收需两端记录版本：双向 Ping、语音进出不改变 ET 代次、P2P 持续
收到音频时不因单次缺统计拆线、真实停流能回退以及退出后规则按归属清理。
未采集用户音频，未运行会触发 Windows 网络提示的 Go/真实 ICE 套件。
没有触发 GitHub CI。
