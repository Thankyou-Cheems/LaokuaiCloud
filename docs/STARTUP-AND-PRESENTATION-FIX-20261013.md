# .10 启动与提示修复

用户在 .9 普通双击启动时遇到主进程异常：
`dialog module can only be used after app is ready`。

## 根因与修复

.9 的管理员入口在模块初始化阶段同步调用 `dialog.showMessageBoxSync`。
已有单元测试替换了弹窗，未模拟 Electron 的 ready 限制；离线整包启动则有意
跳过管理员入口，不能覆盖这个错误。保留 .9 的历史通过记录，同时明确它们的
覆盖边界和此次真实失败，不能把隔离启动通过当作普通启动验收。

独立的轻量入口先同步验证管理员权限。已经是管理员时才导入主应用，保留原来
的 ready 前配置顺序；非管理员分支安排一个等待 `app.whenReady()` 的提示任务，
不导入主应用。入口模块本身不等待这个任务，从而让 Electron 完成 ESM 加载并
发出 ready。拒绝、取消 UAC 或重启失败仍退出；配置、单实例锁、窗口及 ET
初始化均在被隔离的主应用模块中，没有新增提权方式或持久服务。

曾试验在主模块顶层直接等待 ready，实际 ESM 夹具证明这会阻塞 ready，已舍弃；
仅 CJS 异步函数测试不能发现这一点。最终对照使用真实 ESM 顶层加载，验证入口
先完成求值，再在 ready=true 时到达提示边界。构建保留动态导入边界，包审计
沿主入口的实际静态/动态相对导入核对所有可达主进程块，拒绝缺失或越界路径。

回归测试提取实际 main 入口块，先证明旧代码在 ready=false 调用弹窗，再验证
新代码等待 ready，并在选择退出后不继续配置初始化。另用实际 Electron 40.6.1
生命周期重复对照：旧代码由真正的 dialog 模块抛出上述异常，新代码到达弹窗
边界时 ready=true。该夹具模拟普通用户的令牌结果与退出选择，不显示真实 UAC，
不接触实际账号、社区、ET、驱动或防火墙。真实按钮交互仍需用户测试。

## 提示音和聊天区域

同时按用户反馈提高未自定义过的曼波播报默认音量，并把奇丽叶插画接入真实聊天
消息区域；保留手动音量、静音、通知输出设备、原主题及消息滚动/输入行为。
对应的参数、渲染检查与最终产物身份以本次源码及包回执为准。

测试音频仍为 .9 已确认的九条静态文件，不调用在线 TTS。此次只发布新的客户端
测试包，不修改 Gryt、SFU、EasyTier 公共节点或管理代理服务。
