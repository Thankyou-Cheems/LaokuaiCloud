# 双击增量更新

交付：`唠蒯云-15到16-双击更新.exe`，约 16.0 MB。
精确源码、哈希与验证结果见[发布回执](../release/acceptance/native-incremental16-20261014.json)。

`.15 → .16` 提供一个独立 Windows EXE，内嵌已冻结的增量数据。使用系统自带的
.NET Framework，不要求用户安装 PowerShell 7、7-Zip 或 Node.js。
开发构建和自动化测试仍使用 PowerShell 7，用户运行更新器不调用 PowerShell。

## 用户操作

1. 从托盘退出唠蒯云，然后双击更新 EXE。
2. 更新器查找桌面、快捷方式和附近目录中的旧版，并校验程序文件。
   仅找到一份安装且是匹配旧版时自动更新；新旧版并存或多份旧版时选择要更新的位置；
   找不到时手动选文件夹。
3. 完成后重新打开原文件夹中的唠蒯云。重复运行已更新的版本不会再次替换文件。

它不会扫描整个硬盘，不强制结束正在运行的应用，也不会启动应用或修改系统网络规则。
应用仍在运行时，退出应用后在更新器重试即可。

## 数据与恢复边界

只替换固定清单中的程序文件，账号、配置以及目录中的其他文件不参与替换。
先验证完整旧版、增量数据和重建结果，再写入安装目录；旧程序保存在同级恢复目录。
捕获到更新失败时回滚。异常断电或进程被终止后的恢复目录会保留，不能将其当作
一次成功更新，也不能在未确认恢复状态时继续覆盖。

这是精确的 `.15 → .16` 更新，不是任意旧版通用补丁。文件被修改、版本不匹配
或路径存在不安全重定向时拒绝更新；不能靠忽略校验强行安装。
程序更新临时材料放在安装位置旁边，不解压到系统 TEMP。

## 对应源码与验证

更新器构建时嵌入增量 ZIP 的 SHA256、精确源码链接和许可证；源码在本公开仓库，
不随更新包附带源码归档。运行时应用内容与既有 `.16` 标准包保持一致，
这次分发方式调整没有修改语音、EasyTier 或服务器。

合成夹具通过生产更新引擎验证拒绝错误输入、保护账号和回滚行为；真实 `.15`
归档重建结果另外逐文件对照 `.16`。具体结果与产物哈希记录在发布回执，
不以这些文件更新检查代替真实双机语音验收。

构建命令（仅开发者执行）：

```powershell
./tools/new-native-incremental-update.ps1 `
  -UpdateZip '<已冻结增量ZIP>' -ExpectedPackageSha256 '<发布记录中的SHA256>' `
  -SourceCommit '<已提交更新器源码的40位commit>' -OutputExe '<新的输出EXE路径>'
```

构建器拒绝与指定提交不一致的输入；更新器源文件、固定路径清单、图标、许可和
生成的版本信息均记录输入哈希。`.build.json` 记录产物及嵌入增量的哈希，
构建成功本身不表示运行验证通过。产物未作发布者数字签名，包内哈希用于校验完整性。
