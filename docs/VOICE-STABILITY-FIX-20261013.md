# 双人语音与 EasyTier 独立性修复

2026-10-13，针对用户 `.10` 双设备实际失败。该失败不被之前的隐藏启动、
单机 DNS 或模拟媒体通过结果覆盖。新包仍需真实双人可听与回退验收。

## 已确认问题

1. 普通 CLI/binding 读取持续失败，会被 enrollment 的恢复任务放大为 core
   关闭、撤销凭据和重新入网。语音变化不应触发这一生命周期。
2. 远端成员正常加入/离开改变音频接收白名单，原实现关闭整个 SFU PC；
   本机记录的 `media-policy-changed` 与这一控制流吻合。
3. P2P 桥在连接已就绪、roster 尚未到达时跳过初始化，后续 roster 更新
   仅更新已有 session，无法创建缺失的 session。
4. 交叉审查发现同 PC/source 退休后重绑会误认为借用的音频边仍连接，
   可能导致持续静音；必须区分媒体连接的实际所有权与选路标签。

## 实现要求与回归边界

EasyTier 的存活会话保持运行；观测错误使证据失效并独立重试。超时取消不能
被误判为核心退出。真实进程退出、身份撤销、凭据到期与主动退出仍执行各自
的清理和恢复。旧轮询的迟到结果不能覆盖新轮询。未知状态不伪装成在线。

语音成员变化按动态接收权限处理；保留严格麦克风来源与 SDP/msid 校验。
移除权限立即禁用相应接收，新增权限经协商确认，不重建整条连接。切换
媒体模式/实际房间生命周期仍遵循独立的连接规则。

P2P 初始化等待本机身份、roster 与 epoch 就绪，远端列表刷新不会反复
创建 owner。同会话重配置保留 SFU 恢复 ACK 门槛；过期异步任务不处置新 owner。

## 本地诊断

沿用 `laokuai-chat-data/laokuai-diagnostics/events.jsonl`，每份最多 2 MiB，
连同两份轮换文件最多约 6 MiB。新增字段只接受固定枚举、布尔值和有界数字：

- ET 状态、generation、启动/停止、CLI/issuer 观测原因。
- 凭据 HTTP 状态与服务端安全错误枚举。
- P2P readiness、路由选择/失败原因、切换版本。
- ICE 候选类型、底层路径分类、解码证明是否新鲜。
- SFU 暂停/恢复请求的 ACK 结果。

账号、成员/房间/track ID、真实或虚拟 IP、SDP、Token、密码、聊天与音频不写入
这些新诊断事件。日志观察者失败不得改变联机或媒体行为。真实用户日志留在
本机私有目录，不进入公开仓库。必要的编号只在当前运行内关联事件。

## 双人测试

双方使用同一新版本，恢复社区后先确认联机；加入同一频道持续双向说话，
观察 P2P/直连证据。退出并重新进入频道，确认另一方不被迫整条语音重连。
若发生自动 SFU 回退，确认仍能听到，且 EasyTier 没有跟随语音切换重启。
失败时记录本地时间，并保留双方诊断文件，避免只用状态标签推断物理路径。

源码与纯逻辑回归不能证明真实 NAT 穿透、双人听感、成员中继或 12 人 WAN
容量；最终包回执单独记录精确源码、检查结果和未验收项。本轮不改变腾讯云
服务配置或 EasyTier 原生二进制，不迁移或重置用户配置。
