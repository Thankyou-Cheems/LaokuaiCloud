# 精简分发与固定目录单 EXE

当前仍使用 Electron + EasyTier 2.7.0。`.14` 完整 ZIP 为162,765,292字节，
释放后395,078,300字节。其中Electron主程序214,117,376字节，应用ASAR约60MB，
EasyTier core与CLI合计约26.4MB。压缩改善下载体积，不减少运行内存。

## 本轮处理

检查发现 `dist-electron` 混入四个旧的 `main-*.js`，合计约11.3MB。
所安装 `vite-plugin-electron` 默认不清空输出，多个入口顺序构建。现在仅第一个
入口清空共享输出，后续入口继续写入；包审计也拒绝未被入口引用的旧主进程块。
`.15` 保持语音、联机、主题、录音和用户数据逻辑，只更新构建与分发。

同一`.14`完整程序的7z对照包为98,251,996字节，相比原ZIP减少39.6%。
`.15` 标准ZIP为159,346,962字节，自解压EXE为111,745,661字节；相对原`.14`
ZIP小31.3%。146项应用文件逐项一致，另保留一份NSIS许可证，见对应交付回执。
`tools/new-compact-package.ps1` 将已经通过审计的程序压为7z，再解开逐项验证
全部文件哈希；不裁剪功能、驱动或许可证，不运行程序或修改桌面。
解压器支持7z时可使用精简包；解压后的应用仍为固定目录，兼容原增量更新方式。

## 单 EXE 的可行边界

现有 electron-builder 便携模板默认把程序写到 `$PLUGINSDIR/app` 或
`$TEMP/<unpackDirName>`，每次运行前与退出后删除；仅设置unpackDirName仍是临时
目录，不能满足此需求。它是自解压封装，不是所有组件直接在一个文件内运行。

可采用专用启动器：将运行文件首次释放到EXE旁的固定子目录，后续校验版本后
直接复用；用户数据独立保存且不随更新删除。更新须等自有应用完全退出再替换，
保留回滚，并延续正常UAC及固定路径防火墙规则。这样可以单文件分发而不向系统
临时目录释放应用，但磁盘上仍有运行目录；首次启动也要等待解压。

用户进一步选择无需7z能力的分发方式，因此本轮改交付自解压绿色EXE：内置
NSIS中文目录选择与释放页，使用非solid的逐文件LZMA，不使用插件DLL、注册表
安装或自动启动应用。拒绝非空目录及TEMP内的显式释放目标，用户在完成后从
固定目录运行应用；解压器可删除。它是一次性分发工具，不是每次启动的包装器。
原目录中已保存的账号不会自动迁入新目录，原用户继续使用增量更新。

构建入口为 `tools/new-self-extract-package.ps1`；
`tools/tests/check-self-extract-package.ps1` 在隔离目录执行真实解压器，校验全部
程序文件与NSIS许可证、中文空格路径、拒绝覆盖与TEMP目标，并观测隔离TEMP的
创建事件。测试不启动释放出的应用，不访问真实账号、ET或麦克风。
精确结果、体积、脚本和编译器哈希以交付回执为准。

观察到每次启动解压器会创建并立即删除一个 `ns*.tmp` 可写性探测文件，符合
[NSIS 3.0.4 启动源码](https://github.com/NSIS-Dev/nsis/blob/v304/Source/exehead/Main.c#L71-L80)。
应用与EasyTier文件直接写入目标目录，未观察到临时应用副本或残留；不能将此
描述为“整个进程完全不访问TEMP”。首次试验还发现新目录规范化返回空的问题，
已修正并保留失败包作为本地证据，不对外分发。

NSIS参数依据[官方压缩文档](https://nsis.sourceforge.io/Docs/Chapter4.html#4.8.2.4)
及[命令行文档](https://nsis.sourceforge.io/Docs/Chapter3.html#3.2)。保持一个EXE
分发和始终只有一个文件运行是不同的要求；本方案释放后仍保留应用目录。
